# `type` vs `enum`

When defining types in TypeScript, I've sometimes wondered whether to use `type` or `enum`.

I personally prefer `type`, but some of my coworkers use `enum`.

Which one is the better choice?

## `type`（union）

`type` is a type-only construct that disappears at runtime.

It is commonly used to define unions of string literals.

```ts
type Status = "ok" | "ng";
```

### Features

- Completely removed from the generated JavaScript
- Has no impact on bundle size
- Easy to extend and modify as a set of string literals
- Cannot be redeclared with the same name, which helps prevent mistakes

## `enum`

`enum` is a set of named constants that generates a JavaScript object at runtime.

```ts
enum Status {
  OK = 200,
  NG = 400,
}
```

### Features

- Supports both numeric and string values
- Can be used as both a type and a set of constants
- Can be enumerated at runtime because it exists as a JavaScript object
- Declarations with the same are automatically merged

## When to Use `type` vs `enum`

### ① As a General Rule, Prefer `type`

```ts
type Role = "admin" | "user";
```

#### Why?

- Lightweight because it has no impact on bundle size
- Cannot be redeclared, making unintended changes less likely
- Works well with React because UI state can be managed safely with types

### ② When to Use `enum`

```ts
enum HttpStatus {
  OK = 200,
  NotFound = 404,
}
```

- When working with numeric constants such as HTTP status codes
- When you want to group related constants together
- When you need to enumerate values at runtime (for example, for logging, loops, or API responses)

# I Stopped Using opusplan and Plan Mode: The Main Agent Does PM and Review, Subagents Do Research, Design, and Development

I previously wrote about how I worked with opusplan mode and plan mode in Claude Code. I've since changed how I work, so this post explains why.

To start with the conclusion: I stopped using opusplan and plan mode. Now the main agent, running on Opus, handles PM and review, and I leave research, design, and development to Sonnet subagents.

## The Previous Workflow

Here's a quick recap.

- With opusplan mode, research and design ran on Opus and development ran on Sonnet
- I had it create a plan document in plan mode
- Once the plan document was ready, I cleared the context and moved on to development

As a way to reduce tokens, I quite liked it.

## Why I Stopped

There are two reasons.

- **In Claude Desktop, clearing the context has to be done by hand, which is a hassle.** Clearing it myself every time a plan document was finished felt like a chore.
- **Even small tasks ended up with a plan document, which felt like a waste of tokens.** Having it write a plan for even a tiny fix was overkill.

I started to feel that a mechanism meant to save tokens was actually using more of them.

## The Current Workflow

I changed the division of roles as follows.

- Main agent (Opus): handles PM and review
- Subagents (Sonnet): handle research, design, and development

PM and review, where the quality of judgment matters, go to Opus, the higher-tier model. Research, design, and development, the hands-on work, go to Sonnet to keep token usage down.

Instead of relying on switching modes, I now choose the model by the role itself. I also no longer have to clear the context for a plan document.

## Summary

- I stopped using opusplan and plan mode
- In Desktop, clearing the context is manual, and that was a hassle
- Even small tasks needed a plan document, and the wasted tokens bothered me
- Now the main agent runs on Opus for PM and review, and Sonnet subagents handle research, design, and development

Rather than adding more mechanisms, splitting models by role suited me better as a way to reduce tokens.

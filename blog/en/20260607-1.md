# Updating State With `prev` in React `useState`

In React's `useState`, you should use `prev` when the next state depends on the current state.

## Why `prev` Is Necessary

``` ts
setCount(count + 1);
setCount(count + 1);
// 0 + 1
// 0 + 1
```

The result is `1` because both updates refer to the same `count`.

However, when you use `prev`, each update receives the latest state value, so the updates are applied in sequence.

```ts
setCount(prev => prev + 1);
setCount(prev => prev + 1);
// 0 → 1 → 2
```

This is because React does not update state immediately.
Instead, state updates are queued and processed during the next render.

Therefore, when the next state depends on the current state, using `prev` is the safest approach.

## Updating a Single Value（e.g., `boolean`）

The current value is toggled.

```ts
const [isOpen, setIsOpen] = useState(false);
setIsOpen(prev => !prev);
// false → true
// true → false
```

## Updating Array State

Only the value at the specified `index` is toggled.

```ts
const [arrStates, setArrStates] = useState<boolean[]>(
  [false, false, false]
);
const updatedAA = (index: number) => {
  setArrStates(prev =>
    prev.map((v, i) =>
      i === index ? !v : v
    )
  );
};
```

## My Thoughts

When the next `state` depends on the current `state`, you should use `prev`.

Using code like this:

```ts
setCount(count + 1);
```

can lead to unintended values during consecutive updates and may cause bugs.
Also, `prev` is just a parameter name, so you can rename it to anything you like.

Understanding why `prev` exists helped me better understand how React handles state updates.

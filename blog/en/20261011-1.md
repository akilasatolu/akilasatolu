# How I Use AI With Claude Code: No Skills, Everything Runs on My Own Platform

This post summarizes how I currently work, assuming Claude Code.

To start with the conclusion: I don't use skills. I do all of my work on an agent platform that I built myself, and the main agent takes on almost every role. The only thing I hand off to a subagent is review.

## Why I Don't Use Skills

There are two reasons.

- **Applying them to both local and cloud is a hassle.** Once you create a skill, you have to keep it in sync. Doing that on every update became a chore, and I ended up not using them.
- **Remembering commands is tiring.** The more there are, the more often I think, "What was that one called again?" I'm asking AI for help, so it felt wrong that the amount I have to remember keeps growing. I never really came to like them.

## Operating Everything From the Platform

I wanted a single entry point, so I built a platform for running AI agents. Now, whatever I do, I do it from there.

I don't have to remember commands, and I don't have to worry about syncing between environments.

## The Main Agent Takes On Almost Every Role

There are five roles: research, design, development, PM, and review.

Except for review, I basically leave all of them to the main agent.

If you split the work across subagents, you have to hand over context every time. That costs extra time and tokens. Splitting things up looks more organized, but in practice it only increased the cost.

That said, leaving everything to the main agent doesn't mean I give it all the information from the start. I give it the information for each role at the moment that role is needed: research information when researching, design information when designing.

## Only Review Goes to a Subagent

For review, I want a third-party view with no preconceptions.

The main agent knows the whole story from research through design and development, so it inevitably goes easy on its own work. A subagent that doesn't know the background judges based only on the work itself. This is the one place where I think the cost of handing over context is worth paying.

## Mode Settings for Reducing Tokens

### opusplan Mode

Research and design are done with Opus, because the quality of the decisions matters.

For development, it switches to Sonnet. As long as the plan is solid, Sonnet handles it well enough, and it also cuts token usage.

### Creating a Plan Document in Plan Mode

I use plan mode to have it write a plan document first. Development then proceeds based on that plan.

### Clearing the Context Once the Plan Is Ready

This is quietly effective. The trial and error from research and design is almost never needed during development. If I keep only the plan document, clear the context, and then start development, the agent doesn't have to read unnecessary context, and that saves tokens.

## Summary

- I don't use skills, because syncing them and remembering commands is too much of a burden
- I do everything from my own platform
- The main agent handles everything except review, and gets information only when it's needed
- Review goes to a subagent with no preconceptions
- With opusplan, research and design use Opus, and development uses Sonnet
- I create a plan document in plan mode, then clear the context before development

Rather than adding more agents, concentrating the work in the main agent and separating out only review feels just right for me.

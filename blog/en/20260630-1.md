# Ruby on Rails Study Log

These are my notes on learning the basics of Ruby on Rails.

## Creating a Rails Application

Create a new Rails project.
```Bash
rails new Project_Name
```

Start the Rails server.
```Bash
bin/rails server
# or
rails s 
```
You can see your Rails application by visiting `localhost:3000` in your browser.

## Rails Directory Structure

In Rails, you mainly write your application code under the `app/` directory. 
```
app/
  ├── controllers
  ├── models
  └── views
```

Rails follows the MVC architecture.
- M = Model(handles data and business logic)
- V = View(displays the user interface)
- C = Controller(handles requests and coordinates the application)

A request is processed as follows:

1. Browser
2. Controller
3. Model
4. Controller
5. View
6. Browser

More simply, the flow looks like this:

1. URL
2. Routing
3. Controller
4. View

## Routing

Routing connects URLs to controllers.

Configuration File
```ruby
config/routes.rb 
```

Example
```ruby
Rails.application.routes.draw do  
  get "/users", to: "users#index"
end 
```

How it works
```
/users
↓
UsersController
↓
index 
```

Example
```ruby
Rails.application.routes.draw do
  resources :todos
  root "todos#index"
end
```
`resources :todos` automatically creates seven routes.
You can view them by running `rails routes`.

```
GET    /todos
GET    /todos/new
POST   /todos
GET    /todos/:id
GET    /todos/:id/edit
PATCH  /todos/:id
DELETE /todos/:id
```

## Rails Naming Conventions

Rails relies heavily on naming conventions.

For example:
```ruby
UsersController 
```
is automatically mapped to:
```
app/controllers/users_controller.rb 
```

Similarly, `User` model maps to the `users`table.

Rails follows these naming conventions:

```
Model → Singular
Table → Plural
```

## Controller

A controller receives requests, interacts with models, and renders views.

```ruby
class UsersController < ApplicationController
  def index
  end
end 
```

## View

A view is responsible for rendering the user interface.

`UsersController#index` renders `app/views/users/index.html.erb` by default.

## ERB(Embedded Ruby)

ERB lets you embed Ruby code in HTML.

```erb
<%= "Hello Rails" %>
<!-- Hello Rails -->

<%= 1 + 2 %>
<!-- 3 -->

<%= Time.now.year %>
<!-- 2026 --> 
```

Use `<% %>` to execute Ruby code without producing any output.
```erb
<% users = ["Alice", "Bob"] %> 
```

## Displaying a List with `each`

```erb
<% users = ["Alice", "Bob", "Carol"] %>
<ul>
  <% users.each do |user| %>    
    <li><%= user %></li>  
  <% end %>
</ul> 
```

Output
```html
<li>Alice</li>
<li>Bob</li>
<li>Carol</li> 
```

## Passing Data from a Controller to a View

Use an instance variable to pass data from a controller to a view.

```ruby
# Controller
class UsersController < ApplicationController  
  def index    
    @message = "Hello Rails"  
  end
end 
```

```erb
<!-- View -->
<h1><%= @message %></h1> 
```

```html
<!-- Output -->
<h1>Hello Rails</h1> 
```

Instance variables (such as `@message`) are shared between a controller and its view.

Local variables cannot be shared with a view, so they cause an error.

## Model

A model is responsible for handling data.

```ruby
class User < ApplicationRecord
end 
```

models interact with the database.

For example, you can retrieve data from the `users` table like this:
```ruby
User.all 
```

## What Is Active Record?

Active Record lets you work with database records as Ruby objects.

Normally, you retrieve data by writing SQL queries.
```sql
sql SELECT * FROM users; 
```

In Rails, you can do the same thing like this:

```ruby
User.all 
```

This produces the same result without writing SQL.

## What Is ORM?

ORM(Object-Relational Mapping) is a technique that maps objects to database records.

```
Ruby Objects
↓
SQL
↓
Database 
```

In Rails, Active Record works as the ORM. 
```
Ruby
↓
ActiveRecord
↓
Database
```

## Common Active Record Methods

Retrieve all records
```ruby
User.all 
```

Retrieve a record
```ruby
User.find(1) 
```

Retrieve records that match a condition
```ruby
User.where(name: "Alice") 
```

Create a record
```ruby
User.create(name: "Alice") 
```

Update a record
```ruby
user = User.find(1)
user.update(name: "Bob") 
```

Delete a record
```ruby
user.destroy 
```

## How `User.all.each` works
```ruby
User.all.each do |user|
end 
```

It does not retrieve one record at a time from the database.

First, it retrieves all records with:
```ruby
User.all 
```

Then, it processes them one by one like an array using:
```ruby
.each 
```

## Migration

A migration defines the structure of the database.

Normally, you create database tables using SQL, but in Rails you define them in Ruby using migrations.

```ruby
class CreateUsers < ActiveRecord::Migration[8.0]  
  def change    
    create_table :users do |t|      
      t.string :name      
      t.timestamps
    end  
  end
end 
```

## Creating a Model

You can create a model and a migration at the same time.

```bash
rails generate model User name:string 
# or 
rails g model User name:string 
```

```
<!-- Generated files -->
app/models/user.rb
db/migrate/20260610000000_create_users.rb 
```

The `User` model is automatically mapped to the `user` table.
```
User
↓
users table
```

## Running Migrations

Apply the migration to the database.
```bash
rails db:migrate 
```

After running the migration, `db/schema.rb` is generated.

`schema.rb` contains the latest database schema.

## CRUD

CRUD is the foundation of data operations.
```
C = Create
R = Read
U = Update
D = Delete 
```

For example, in a social media app:

| CRUD | Example |
|--------|--------|
| Create | Create a post |
| Read | View posts |
| Update | Edit a post |
| Delete | Delete a post |

## Create
```ruby
User.create(name: "Alice") 
# or
user = User.new(name: "Alice")
user.save 
```

## Read
```ruby
User.all
User.find(1)
User.where(name: "Alice") 
```

## Update
```ruby
user = User.find(1)
user.update(name: "Bob") 
# or
user.name = "Bob"
user.save 
```

## Delete
```ruby
user = User.find(1)
user.destroy 
```

## CRUD Actions in Rails

Rails follows conventions for CRUD actions.

| CRUD | Action |
|--------|--------|
| Create | new / create |
| Read | index / show |
| Update | edit / update |
| Delete | destroy |

Controllers typically define the following action methods:

```ruby
# List
def index
end

# Show details
def show
end

# Display the new form
def new
end

# Create a new record
def create
end

# Display the edit form
def edit
end

# Update a record
def update
end

# Delete a record
def destroy
end 
```

## Using Active Record in a View

```ruby
# Controller
def index  
  @users = User.all
end 
```

```erb
<!-- View -->
<ul>  
  <% @users.each do |user| %>    
    <li><%= user.name %></li>  
  <% end %>
</ul> 
```

```erb
<!-- Conditional Rendering -->
<% if @users.any? %>  
  Users exists
<% else %>  
  No users
<% end %> 
```

## What Is `params`?

`params` is used to retrieve values passed in the URL or an HTTP request.

For example, if you access `/users/1`, `params[:id]` will be `1`.

Therefore, `User.find(params[:id])` is equivalent to `User.find(1)`.

# I Tried to Improve My Workflow, and Keeping the Current One Turned Out Best

My current workflow has the main agent (Opus) handle PM and review, and leaves research, design, and development to subagents (Sonnet).

I wondered whether it would be faster and more accurate for the main Opus to do research, design, and development itself, and hand only the review to a separate Opus subagent. If the higher-tier model works directly, there should be less rework and fewer handoffs of instructions.

But changing a workflow based on a guess alone is risky, so I ran the same tasks in both setups and compared them. From here on, I'll call the current setup "Current" and the new idea "Proposal."

## How I Compared Them

I prepared three tasks of different sizes and ran each one once in both setups, for six runs in total.

- Task A (small): add one option to a function and update the README
- Task B (small to medium): add unit tests for six functions and fix the bugs they uncovered
- Task C (medium): in a repository of about 200 files, investigate how the search score is determined

The request text and the review criteria were the same for both.

## Results

| | Current (Sonnet works, main agent reviews) | Proposal (Opus works, Opus reviews) |
| --- | --- | --- |
| Total agent run time | About 5 min | About 14 min |
| Tokens read by subagents | About 1.5M (Sonnet) | About 4.15M (Opus) |
| Findings in the first review | A: 0, B: 0, C: 3 (2 of them major) | 1 each for A, B, and C (all minor) |

Speed was the opposite of what I expected. The Proposal took about 2.7 times as long, used about 2.8 times as many tokens, and spent them on Opus, which costs more per token.

Accuracy was better with the Proposal. The difference was biggest in research (Task C), where the first output from Current contained two factual errors. However, that difference came not from handing the review to a separate agent, but from Opus doing the work.

## I Kept the Current Workflow

Although the Proposal was more accurate, it takes about 2.7 times as long and about 2.8 times as many tokens. I decided that this was not a reason to change the workflow, and I kept the current one. For a small, routine task (Task A), both gave the same result, and Sonnet finished in about a third of the time and tokens.

Instead, I found one thing I could fix within the current workflow. When reviewing research, I should not stop at checking the cited passages against the source, but also read beyond them to confirm nothing is missing.

I had expected that "it would be faster if the higher-tier model did it directly," but the measurements showed the opposite. I'm glad I tested it on a small scale before changing my workflow.

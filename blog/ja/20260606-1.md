# `type` と `enum`

TypeScriptで型を定義する際、`type`を使うべきか`enum`を使うべきか迷うことがある。

私は個人的に`type`派だが、同僚には`enum`を使う人もいる。

どちらがより良い選択なのだろうか。

## `type`（ユニオン型）

`type`は型のみの構文で、実行時には消える。

文字列リテラルのユニオン型を定義する際によく使われる。

```ts
type Status = "ok" | "ng";
```

### 特徴

- 生成されるJavaScriptから完全に消える
- バンドルサイズに影響しない
- 文字列リテラルの集合として拡張・変更がしやすい
- 同じ名前で再宣言できないため、ミスを防ぎやすい

## `enum`

`enum`は名前付き定数の集合で、実行時にJavaScriptのオブジェクトを生成する。

```ts
enum Status {
  OK = 200,
  NG = 400,
}
```

### 特徴

- 数値・文字列どちらの値もサポートする
- 型としても定数の集合としても使える
- JavaScriptオブジェクトとして存在するため、実行時に列挙できる
- 同じ名前の宣言は自動的にマージされる

## `type`と`enum`の使い分け

### ① 基本的には`type`を優先する

```ts
type Role = "admin" | "user";
```

#### 理由

- バンドルサイズに影響しないため軽量
- 再宣言できないため意図しない変更が起きにくい
- 型で安全にUIの状態を管理できるため、Reactと相性が良い

### ② `enum`を使うべき場面

```ts
enum HttpStatus {
  OK = 200,
  NotFound = 404,
}
```

- HTTPステータスコードのような数値定数を扱う場合
- 関連する定数をまとめてグループ化したい場合
- 実行時に値を列挙する必要がある場合(ログ、ループ、APIレスポンスなど)

# React `useState`で`prev`を使って状態を更新する

Reactの`useState`では、次のstateが現在のstateに依存する場合、`prev`を使うべきだ。

## なぜ`prev`が必要なのか

``` ts
setCount(count + 1);
setCount(count + 1);
// 0 + 1
// 0 + 1
```

両方の更新が同じ`count`を参照するため、結果は`1`になる。

しかし`prev`を使うと、それぞれの更新が最新のstateの値を受け取るため、更新が順番に適用される。

```ts
setCount(prev => prev + 1);
setCount(prev => prev + 1);
// 0 → 1 → 2
```

これは、Reactがstateを即座に更新しないためだ。
代わりに、state更新はキューに入れられ、次のレンダー時に処理される。

そのため、次のstateが現在のstateに依存する場合は、`prev`を使うのが最も安全な方法だ。

## 単一の値を更新する(例: `boolean`)

現在の値がトグルされる。

```ts
const [isOpen, setIsOpen] = useState(false);
setIsOpen(prev => !prev);
// false → true
// true → false
```

## 配列のstateを更新する

指定した`index`の値だけがトグルされる。

```ts
const [arrStates, setArrStates] = useState<boolean[]>(
  [false, false, false]
);
const updatedAA = (index: number) => {
  setArrStates(prev =>
    prev.map((v, i) =>
      i === index ? !v : v
    )
  );
};
```

## 感想

次の`state`が現在の`state`に依存する場合は、`prev`を使うべきだ。

以下のようなコードを書くと:

```ts
setCount(count + 1);
```

連続した更新の際に意図しない値になり、バグの原因になることがある。
また、`prev`は単なる引数名なので、好きな名前に変更しても構わない。

なぜ`prev`が存在するのかを理解したことで、Reactがstateの更新をどう扱うかをより深く理解できた。

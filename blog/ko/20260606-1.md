# `type` vs `enum`

TypeScript에서 타입을 정의할 때 `type`을 써야 할지 `enum`을 써야 할지 고민한 적이 있다.

나는 개인적으로 `type`을 선호하지만, 동료 중에는 `enum`을 사용하는 사람도 있다.

어느 쪽이 더 나은 선택일까?

## `type`(유니온)

`type`은 타입 전용 구문으로 런타임에는 사라진다.

문자열 리터럴의 유니온을 정의할 때 흔히 사용된다.

```ts
type Status = "ok" | "ng";
```

### 특징

- 생성된 JavaScript에서 완전히 제거된다
- 번들 크기에 영향을 주지 않는다
- 문자열 리터럴 집합으로서 확장하고 수정하기 쉽다
- 같은 이름으로 재선언할 수 없어 실수를 방지하는 데 도움이 된다

## `enum`

`enum`은 이름이 붙은 상수의 집합으로, 런타임에 JavaScript 객체를 생성한다.

```ts
enum Status {
  OK = 200,
  NG = 400,
}
```

### 특징

- 숫자값과 문자열값을 모두 지원한다
- 타입으로도, 상수 집합으로도 사용할 수 있다
- JavaScript 객체로 존재하기 때문에 런타임에 열거할 수 있다
- 같은 이름의 선언은 자동으로 병합된다

## `type`과 `enum`을 언제 사용할까

### ① 기본적으로는 `type`을 선호한다

```ts
type Role = "admin" | "user";
```

#### 이유

- 번들 크기에 영향이 없어 가볍다
- 재선언이 불가능해 의도치 않은 변경 가능성이 적다
- 타입으로 UI 상태를 안전하게 관리할 수 있어 React와 잘 맞는다

### ② `enum`을 사용해야 할 때

```ts
enum HttpStatus {
  OK = 200,
  NotFound = 404,
}
```

- HTTP 상태 코드처럼 숫자 상수를 다룰 때
- 관련된 상수를 함께 그룹화하고 싶을 때
- 런타임에 값을 열거해야 할 때(로깅, 반복문, API 응답 등)
